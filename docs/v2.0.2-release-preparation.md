## 腳本用法與發布順序（由 gm 審、JJ 執行）

`publish-v202.sh` 可由 gm 複製到 `~/scripts/`；預設產物仍讀取 `~/Developer/jig-network-release-20261105/`。私鑰不在腳本與產物中，只有公開金鑰；latest.json 已用既有設定簽章並以客戶公鑰驗證。

發行 repo 分兩個 commit：第一個是程式／文件／releases/2.0.2，第二個才是 shared/latest.json 與 .sig。**不可先 push 分支 HEAD**，否則自動更新可能先提示客戶、附件仍是 404。

1. gm 審查 core commit、發行準備 commit、手冊來源；JJ 依原流程只 push 準備 commit（不要包含第二個 manifest commit）。
2. 設 `JIG_RELEASE_TARGET` 為已 push 且經 gm 審過的發行準備 commit 完整 SHA；以下 `<prepared-dist-commit>` 需替換。腳本確認該 SHA 遠端存在。

```bash
export JIG_RELEASE_TARGET=<prepared-dist-commit>
bash ~/Developer/jig-network-release-20261105/publish-v202.sh preflight
bash ~/Developer/jig-network-release-20261105/publish-v202.sh publish
bash ~/Developer/jig-network-release-20261105/publish-v202.sh verify
```

3. publish 先建 draft，上傳全部固定白名單、列資產、下載回來比雜湊及簽章，通過才公開，再驗一次。發版後才由 JJ push 第二個 manifest commit，依舊流程檢查 raw latest.json／.sig。
4. 新版本下載驗證完成後，才由 JJ 執行：

```bash

```

delete-xampp 先 verify v2.0.2，再一次檢查 16 個 ID 名稱必須是預期 exe/dmg，全部正確才刪；已刪 ID 重跑會略過。每刪一個輸出 ID，任何 API 失敗立刻停止。GitHub 不支援 16 次刪除的交易：中途斷線已刪項目無法自動回復，需看輸出確認再重跑；腳本不宣稱能原子回滾。上傳失敗保留未公開 draft 供 gm 檢查，不會自動破壞性刪 draft；preflight 偵測既存 draft 會停止，不能盲目重跑 publish。
